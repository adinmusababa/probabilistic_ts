# Fix: Guard rounding of metric columns with null values

## What was changed
- **File:** `src/evaluation/compare_runs.py`
- **Location:** In `summary_table()` the rounding step was updated.
- **Old behavior:**
  ```python
  df = df.with_columns([pl.col(c).round(digits) for c in METRIC_COLS if c in df.columns])
  ```
  This attempted to round **all** metric columns listed in `METRIC_COLS`. When a column (e.g., `nll_ch`) contained only `null` values because the learner did not compute NLL, Polars raised an `InvalidOperationError` as rounding is unsupported for the `null` dtype.
- **New behavior:**
  ```python
  # Round only numeric metric columns; skip any column that contains nulls (e.g., nll_ch when NLL not computed)
  numeric_cols = [c for c in METRIC_COLS if c in df.columns and df[c].dtype.is_numeric()]
  df = df.with_columns([pl.col(c).round(digits) for c in numeric_cols])
  ```
  We now filter `METRIC_COLS` to keep only columns whose datatype is numeric before rounding, preventing errors when NLL metrics are absent.

## Why this fix was needed
The test `test_eval_json_is_compatible_with_compare_runs` creates an evaluation JSON where `nll_total` is `None` (the default for learners that do not implement NLL). Loading this JSON via `load_runs()` yields a `null` value for `nll_ch`. The original rounding step tried to round this null column, causing a failure:
```
polars.exceptions.InvalidOperationError: rounding ('half_to_even') operation not supported for dtype `null`
```
Guarding the rounding step makes the summary table generation robust to missing NLL data, which is a legitimate scenario for many learners.

## Impact
- All existing functionality remains unchanged for runs that provide numeric NLL values.
- Runs without NLL now generate a summary table without error.
- The fix is defensive, covering any future metric column that might be nullable.
